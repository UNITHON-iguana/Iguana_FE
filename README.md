# 현장노트 AI

건설현장 사무·공무 담당자가 텍스트가 포함된 현장 사진을 여러 장 올리면, AI가 사진과 텍스트를
분리하고 구조화된 공사 데이터로 정리한다. 사용자는 결과를 검수·수정하고 계획 대비 공정과 자재
사용 현황을 확인한 뒤 엑셀 또는 사진대지로 내보낸다.

현장 노동자는 기존처럼 메신저로 사진을 전달하며, 이 서비스의 직접 사용자가 아니다.
데스크톱 웹 전용이다.

## 기술 스택

|           |                                       |
| --------- | ------------------------------------- |
| 빌드      | Vite 8 + React 19 + TypeScript        |
| UI        | Ant Design v6 (한국어 로케일)         |
| 라우팅    | React Router v7                       |
| 서버 상태 | TanStack Query v5                     |
| 엑셀      | ExcelJS (계획 데이터 읽기 / 내보내기) |

## 시작하기

```bash
npm install
cp .env.example .env   # VITE_API_BASE_URL 설정
npm run dev
```

| 스크립트         | 설명                      |
| ---------------- | ------------------------- |
| `npm run dev`    | 개발 서버                 |
| `npm run build`  | 타입 체크 + 프로덕션 빌드 |
| `npm run lint`   | ESLint                    |
| `npm run format` | Prettier                  |

## 구조

```
src/
  api/        도메인별 데이터 함수 — 화면은 여기만 호출한다
  mocks/      프로토타입용 인메모리 목 데이터
  app/        프로바이더, 라우터, QueryClient
  layouts/    AppLayout (헤더 + 사이드 내비)
  pages/      프로젝트 · 계획 데이터 · 업로드/분석 · 검수 · 비교 · 내보내기
  features/
    photo-sheet/  사진대지 양식 편집 격자 (antd Table 미사용, CSS Modules)
    export/       엑셀(XLSX) 생성
  lib/        API 클라이언트, 상수
  types/      도메인 타입
```

`@/*` 별칭이 `src/*`를 가리킨다.

### 데이터 계층 규칙

화면은 `fetch`나 `axios`를 직접 부르지 않고 `src/api/*`의 도메인 함수만 호출한다.
지금은 그 함수들이 `src/mocks`의 목 데이터를 돌려주고, 백엔드가 붙으면 `src/api` 안쪽만
HTTP 호출로 바꾸면 화면 코드는 그대로 둔다.

분석 진행 상태는 TanStack Query의 `refetchInterval` 폴링으로 갱신한다.
백엔드가 충분히 빨라 한 번에 결과가 오면 그 옵션만 빼면 된다.

### 미확정 사항

기능명세가 초안이라 아래는 아직 모델링하지 않았다. 확정되면 `src/types`에 필드를 더한다.

- 항목별 AI 신뢰도, 확인 필요 사유
- OCR 원문 노출 여부
- 검수 이력(수정자·수정 시각)
- 사진대지 엑셀 출력 — 지금은 집계용 평면 표만 나가고, 원본 양식 형태로는 아직 안 나간다
- 로그인·권한 (프로토타입에서는 제외)

### 사진대지 뷰

`features/photo-sheet`의 `PhotoSheetGrid`는 원본 엑셀 사진대지 양식을 화면에서 그대로
편집한다. 열 머리글 없이 `구 분`·`작업내용`·`위 치` 라벨이 셀 안에 들어가는 양식이라
antd `Table`에 넣지 않고 순수 `<table>`과 CSS Modules로 짠다.

한 블록은 `사진번호 + 사진 + 작업 항목 줄들 + 위치`로 구성되고, 사진번호와 사진 칸은
그 사진의 모든 줄에 걸쳐 병합된다. 사진 한 장에 작업 항목이 여러 줄 붙을 수 있어 개수를
고정하지 않고, 화면에는 최소 3줄을 빈 칸으로 채워 보여준다.

작업내용은 `규격 + 수량` 한 쌍이고 양식이 한 줄에 두 쌍까지 갖는다. 넘치는 쌍은 칸을
옆으로 늘리지 않고 같은 구분을 단 줄을 하나 더 만들어 아래로 흘린다(`lib/workItems.ts`의
`splitToFormRows`).

PDF 출력과 A4 인쇄 조판은 하지 않는다. 결과물은 엑셀 한 가지다.

### 사진대지 엑셀 출력

사진이 박히고 셀이 병합된 원본 양식 형태의 XLSX는 **백엔드에서 만든다.**
사진 수백 장을 브라우저가 내려받아 메모리에 올릴 수 없고, `exceljs`가 프론트 번들의
931KB(gzip 258KB)를 차지하기 때문이다. 백엔드가 붙으면 프론트는 내려받기 호출만 남기고
`exceljs`를 걷어낸다.

양식 격자는 [docs/사진대지-엑셀-양식-명세.md](docs/사진대지-엑셀-양식-명세.md)에 있다.

현재 `features/export/excel.ts`가 만드는 XLSX는 양식이 아니라 **원시 데이터를 한 줄씩
펼친 표**다. 합계·누계는 없다. 집계표는 아직 만들지 않았다.

## MCP

Ant Design 공식 MCP 서버가 `.mcp.json`에 등록되어 있다. 컴포넌트 API·토큰·예제를 조회해
v6 코드 생성 정확도를 높인다.

## 규칙

사진에서 읽어내지 못한 값은 AI가 임의로 채우지 않는다. 계획 또는 검수 완료된 실적 수량이
없으면 추정하지 않고 `비교 데이터 부족`으로 표시한다.

개별 사진의 분석 실패는 전체 분석 실패로 처리하지 않는다. 실패한 사진도 검수 화면에서
직접 입력할 수 있다.
