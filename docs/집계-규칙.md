# 집계 규칙

집계 화면(`/projects/:id/summary`)이 무엇을 보여주는지 정리한다.
원본은 현장에서 쓰던 엑셀 파일(`BS.xlsm`)이다.

## 계산은 서버가 한다

```
GET /api/v1/projects/{projectId}/aggregation?date=2026-08-20
→ { dates, rows, totalByDate, grandTotal }
```

확정된 사진만 세는 것도, 규격을 갈라 행을 만드는 것도, 가로\*세로를 둘레 연장으로
환산하는 것도 **전부 서버 몫이다.** 프론트에는 더하기·곱하기 규칙이 없다.

프론트가 하는 일은 날짜 열을 고른 달로 좁히거나(`집계표`) 월로 접는 것(`기성누계`)뿐이다
(`src/pages/SummaryPage.tsx`의 `reshape`).

## 행이 갈리는 규칙

공종은 **이름만** 등록한다. 규격은 등록하지 않는다 — 사진마다 AI가 읽는다.
그 규격이 어떤 모양이냐에 따라 서버가 행을 다르게 만든다.

| 사진대지의 규격 | 집계 행 | 값 |
| --- | --- | --- |
| `65` (별표 없음) | 공종 + 규격이 한 행 (`금속관벽체` / `65`) | 수량 그대로 |
| `2000*600` (별표) | 공종 하나가 한 행, 규격은 접힌다 | `(가로+세로)*2/1000 × 수량` |

덕트가 개수가 아니라 **둘레 연장 길이**로 기성을 잡는다는 게 배관과의 결정적 차이다.
`600*400` 덕트 2개는 `(600+400)*2/1000 × 2 = 4.0m`이지 2개가 아니다.

목이 이 규칙을 흉내 내는 코드가 `src/api/aggregation.ts`에 있다.
백엔드가 붙으면 `getAggregation`이 fetch 한 줄이 되고 그 아래는 전부 사라진다.

## 집계표는 한 달치만 본다

작업일이 곧 열이라 기간을 안 자르면 1년짜리 현장에서 열이 이백 개가 되고,
사람이 못 읽는다. 원본 엑셀도 기성 회차마다 시트를 새로 만들어 한두 달치만 담는다
(집계표 열이 17개다).

그래서 집계표 탭에는 **월 선택**을 둔다. 범위 선택이 아니라 월 선택이라 한 달 제한이
구조로 강제된다. 기본값은 **오늘이 든 월**이다.
기성누계는 성격이 반대라 기간을 자르지 않는다.

지금은 전체를 받아 화면에서 자른다. 집계된 숫자라 사진 목록만큼 무겁지는 않지만,
현장이 길어지면 응답에 `from`/`to`가 있어야 한다.

## HB 가공은 뺐다

원본에는 벽체 양면 시공에 2를 곱하는 `HB` 표가 있었다. 프론트에 계수를 두는 설계였는데
공종 API에 그 필드가 없고 기획에서도 빼기로 정해, 관련 코드를 전부 걷어냈다.
다시 필요해지면 서버가 집계할 때 적용하고 응답 행으로 내려주는 게 맞다 —
같은 계수가 프론트와 백엔드 두 곳에 있으면 숫자가 갈린다.

## 내보내기도 서버가 만든다

프론트는 받아서 내려주기만 한다(`src/api/exports.ts`). `exceljs`는 걷어냈다 —
번들이 2,304kB에서 1,401kB로(gzip 694 → 446) 줄었다.

| | 엔드포인트 | 내용 |
| --- | --- | --- |
| 사진대지 | `/export/excel` | 팀 표준 양식. 사진 1장 = 11행 블록, 사진 삽입된 원장 |
| 집계 | `/aggregation/export/excel` | 원본 시트 + SUMIFS 집계표 + 누계. **값이 아니라 수식** |

집계 쪽이 수식이라는 게 중요하다. 엑셀에서 원본 데이터를 고치면 집계표와 누계가
따라 재계산된다 — 프론트가 만들던 값 스냅샷으로는 못 하던 일이다.

두 엔드포인트 모두 `projectId`만 받는다. **화면에서 고른 작업일이나 달은 반영되지 않는다.**

## 아직 안 한 것

- **등록되지 않은 공종을 쓴 줄은 조용히 빠진다.** 예전에는 프론트가 집계하며
  "품목에 붙지 않은 줄"을 세어 알렸는데, 서버가 집계하면서 그 신호가 없어졌다.
  `구 분`을 목록에서 고르게 바꿔 새로 생기지는 않지만, 그 전에 자유 입력으로 들어간
  옛 데이터는 아무도 알려주지 않는다
- **공종 삭제 막기가 절반이다.** 집계에 물량이 있는 공종은 프론트가 삭제를 막는다
  (`TradesPage`의 `inUse`). 하지만 집계는 **확정된 사진만** 세므로, 아직 검수 중인
  사진이 쓰는 공종은 그 눈에 안 보여 지워진다.
  진짜 방어선은 서버다 — 참조가 있으면 409로 거절해야 한다. 명세에는 200만 있다
